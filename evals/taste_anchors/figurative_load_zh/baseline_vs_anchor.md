# Baseline vs Taste Anchor: Figurative Load (ZH)

这组 A/B 文本使用完全相同的虚构事实和结论，只改变表达方式。它用于校准读者审阅，不用于训练，也不提供通用隐喻率阈值。

## 固定事实载荷

- 供应商 A 提供 API 接入和托管工作流两种集成方式。
- 试点涉及 12 家机构，其中 8 家在 30 天后仍使用。
- 材料没有披露付费续约。
- 部署需要私网接入、身份配置和人工审批。
- 当前证据不足以证明规模化商业成熟。

## Baseline 为什么较差

Baseline 在一个短段落中连续切换“引擎、双翼、浪潮、关隘、迷雾、闸门、航道、大船、深水区”等源域。读者需要先还原每个意象，才能恢复客户数、时间窗口、未知数据、部署条件和结论。隐喻没有增加机制解释，反而遮蔽了事实层级与证据边界。

## Taste Anchor 为什么更好

Taste anchor 先直接陈述主体、动作、数据和限制，只保留一个明确标示的软件发布类比，并立即给出字面结论。类比帮助区分试点与规模化两个阶段，但不替代事实，也没有被当作证据。

## Reader Review 判据

不要因为文本含有隐喻就判差，也不要把零隐喻设为目标。逐处判断：意象是否替代了具体主体、动作、机制或证据边界；同一句或同一段是否堆叠无关源域；删除或改写后是否能提高精确度而不损失洞见。只有装饰性或遮蔽性的修辞负荷需要修改。
